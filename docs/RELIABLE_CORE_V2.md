# reliable-core-v2：与原仓库的差异及迁移说明

## 来源与范围

本分支基于原仓库 `main` 的 `f6983fc0308283b1c4574782613222bfa28cd084`。
对照确认：该提交的两份算法源码与 FastPrep 中保留的上游源码完全一致。
迁入的是 FastPrep BFC 1.0.0 的 `reliable-core-v2` 修订，而不是重新实现另一套拟合方法。

`tissue_bfc/support.py`、`validation.py` 与 FastPrep 对应文件保持一致。
CLI 只调整独立仓库内的源码定位、方法专用入口、帮助文字，并为原 RBF
`--max_iter` 保留 `--rbf_max_iter` 的别名。原算法源码移至
`tissue_bfc/_legacy/` 原样保留，供适配层调用数值求解器及复现实验；不建议直接运行旧 CLI。
原 README 保留在 `docs/README-legacy.md`，其中的用法和效果描述不代表新版本。

本次不包含 MRI 数据、私人运行日志、FastPrep runtime、模型权重或许可证文件。
已有示例资源和引用不删除；不修改正在运行的 FastPrep 流程。

## 为什么之前会产生中线附近的亮斑

已完成的对照没有发现 GM/WM 编号接反。关键问题是将**可靠拟合域、组织标签和最终应用域**混用：

1. 标签 0 不只是背景，也可能是脑内未建模的深部结构、小脑或脑干。不参与拟合不等于不需要校正。
2. 旧 Gaussian 最近填充读取的是 `2*nearest-outside` 的反射位置，而非最近可靠点本身；供体可能落入 CSF 等不可靠区域，负 log 残差经平滑累积后造成过亮。
3. 单纯空间腐蚀仍可能保留异常暗的、误标为 WM 的样本。因此还需类内 log 强度离群点筛除。
4. 旧 RBF 将标签 0 清成伪暗背景，软权重可能泄漏；输出时又恢复标签 0 原强度，造成标签边界上的亮度接缝。
5. 首例没有证实脑内 RBF 核权重下溢是原亮斑的原因。稳定 softmax 是独立数值修复，不能据此宣称全部亮斑机制已定位。

## 实现对照

| 环节 | 原版行为 / 风险 | 本分支默认行为 |
| --- | --- | --- |
| 拟合样本 | 标签及平滑先验可能包含边界、误标和伪背景 | GM/WM 分别物理腐蚀 1/2 mm，仅保留正信号；类内 3.5 scaled-log-MAD 筛选 |
| 软权重 | 平滑后可能进入不可靠区 | 仅存在于所属组织的可靠核心，域外严格为零 |
| 样本不足 | 缺少可靠采样域的显式契约 | 明确报错，不回退到污染样本 |
| Gaussian 外推 | 反射点未必是可靠供体 | 按物理距离查找真正的最近可靠供体 |
| Gaussian 迭代 | 原 CLI 可继续更新组织标签 | 固定可靠核心及组织先验，条件化 log10 残差、多尺度平滑累积 |
| RBF 归一化 | 标签 0 伪暗背景、最小值偏移 | 仅按可靠域最大值做比例归一化，无最小值偏移 |
| RBF 核 | 普通指数及分母 epsilon | 拟合和导出均用 log-domain softmax；导出关闭 autograd |
| 最终场应用 | 标签 0 可能恢复原值，产生接缝 | 在完整脑掩膜内连续应用，包括标签 0；脑外及零信号不改 |
| 原始强度 | 原流程存在归一化和裁剪 | 不对校正输出做强度范围裁剪，不改原图或原标签 |
| 有效性 | 输入和场应用契约不完整 | 同一有限非奇异 3D 网格、合法标签、二值掩膜；场整体有限且脑域严格为正 |
| GPU | RBF 可自动回退 CPU | 默认 CUDA；不可用或请求 CPU 时明确失败 |
| 输出 | 可能覆盖既有结果 | 拒绝覆盖，记录支持域、控制点、设备、参数和状态 |

Gaussian 仍保留对**迭代残差**的 `[-0.20, 0.20]` 限幅；这与对最终校正图像做强度裁剪不同。
Gaussian 的 `--modality T2` 固定目标模式只用可靠 GM 残差；默认 `None` 保留拟合类对比。
RBF 原始场是 divisor，Gaussian 是 multiplier。FastPrep 的发布适配器统一转换为 multiplier，
但该独立 CLI 保留原始场约定，并通过 `support.json` 标明。

## 兼容与不兼容

- 两个原文件名仍可执行，但现在进入可靠核心流程；它们不再导出历史脚本的内部函数作为公共 API。
- `python -m tissue_bfc` / `tissue-bfc` 默认 RBF。Gaussian 必须显式选择，或使用 Gaussian 专用入口。
- `--max_iter` 是 RBF `--rbf_max_iter` 的兼容别名。
- `--refine_max_iter` 必须为 0。原 Gaussian 默认更新标签的流程不再是默认路径。
- 不支持 `--batch_size`、`--no_soft_labels`、`--debug`、`--output_points`、`--use_label_value`、`--bspline_grid_size`。这些历史参数会明确报错，不会静默执行别的方法。RBF 控制点始终保存到 `fitted-control-points.npz`。
- 输入必须已经是 `0/1/2/3` 组织编码，且物理单位为 mm；不自动重采样或推断 aseg 映射。
- 样本不足、非法输入、无 CUDA 或输出已存在都可能让原先可运行的命令明确失败；这是有意加强的安全契约。
- 原示例 notebook 留作历史材料，尚未改成新 CLI；不要把旧输出与新实现混为一谈。

## 科学边界

可靠核心并非解剖真值；强真实偏置也可能被 MAD 规则排除。GM/WM 之外的场是外推，
没有独立证据保证深部结构、小脑和脑干都校正正确。之前真实首例中 Gaussian 仍存在
小脑/脑干局部过校正，不能标为 QC 通过；RBF 局部改善也不能外推为所有被试或真实 T2 已通过。

本分支不改变 QC 标准、不提供自动科学批准；`scientific_approval` 始终记录为
`not_performed`。比较方法应保持相同支持域、空间网格、全局标定和显示映射，
不能只看估计场或单一 CV 指标，也不能把程序正常退出当作影像审核通过。
